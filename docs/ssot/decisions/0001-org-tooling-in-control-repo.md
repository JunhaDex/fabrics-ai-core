# ADR 0001: 조직 도구는 메타 저장소에 직접 포함한다

## 상태
승인됨 (2026-09-19)

## 배경
`repo-architecture.md`는 프로젝트 저장소(`projects/<name>/`)를 메타 저장소와
분리된 독립 git 저장소로 관리하는 것을 원칙으로 한다. 이 원칙은 fabrics
업무 산출물(제품/서비스) 프로젝트를 대상으로 수립되었다.

Slack을 통해 Claude Code를 원격으로 트리거하는 운영 도구(`slack-worker`)를
구축하면서, 이 도구를 기존 원칙대로 `projects/`에 독립 저장소로 둘지, 메타
저장소에 직접 포함할지를 결정해야 했다.

## 결정
`slack-worker`처럼 fabrics 업무 산출물이 아니라 **조직 자체의 운영/개발
도구**에 해당하는 항목은 `tools/<name>/` 경로에 두고, 메타 저장소의 git
히스토리에 직접 포함한다(독립 저장소로 분리하지 않는다).

## 근거
- 이 도구는 특정 fabrics 프로젝트의 산출물이 아니라, 메타 저장소 자체의
  운영을 보조하는 인프라이다. `CLAUDE.md`, `.claude/` 설정과 같은 층위로
  취급하는 편이 적절하다.
- 별도 저장소로 분리하면 조직 도구가 늘어날수록 부트스트랩(각 기기에서
  개별 clone)이 오히려 번거로워진다. 메타 저장소는 이미 모든 기기에서 항상
  clone되므로, 조직 도구도 함께 따라오는 편이 실용적이다.

## 범위
이 예외는 **조직 운영 도구**에만 적용된다. fabrics 업무 산출물 프로젝트는
기존 원칙(`projects/<name>/` 독립 저장소)을 그대로 따른다. 조직 도구와
업무 프로젝트의 구분이 모호한 경우, 루트 세션에서 논의 후 결정한다.

## 민감 정보 처리
조직 도구는 메타 저장소에 직접 커밋되므로, 토큰/API 키 등은 반드시
`.env`(루트 `.gitignore`의 `.env`, `.env.*`, `*.pem`, `*.key`, `secrets/`
패턴으로 이미 보호됨) 또는 `secrets/`에 두고, `.env.example`만 커밋한다.
