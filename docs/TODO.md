# 루트 세션 TODO

`0_pjt_fabrics` 루트 세션 자체의 진행 중 작업을 추적한다. 대상은 **메타 작업**만
— SSOT 개정, 신규 프로젝트 부트스트랩 진행 단계, 프로젝트 색인 정비 등.
개별 프로젝트의 작업은 이 문서가 아니라 `docs/<name>-todo.md`
(프로젝트 todo 파일, 아래 절 참고)에서 관리한다.

`docs/PROJECTS.md`가 프로젝트 상태의 **스냅샷**(정본 레지스트리)이라면, 이
문서는 그 상태에 도달하기 위해 **지금 진행 중인 행동**을 담는다.

## 항목 포맷

```markdown
## <제목>
- 컨텍스트: 왜 필요한가, 관련 SSOT 문서/프로젝트
- 상태: not-started / in-progress / blocked(사유) / done
- 다음 행동: 사용자가 할 일 또는 세션에서 이어갈 일
```

## 완료 항목 처리

이 문서(루트 메타 작업)에 한해, 완료된 항목은 삭제한다. 이력은 git log로
대체한다(`docs/ssot/org-principles.md`의 "사실과 예정만 남긴다" 원칙과 동일).
프로젝트 todo 파일은 다르다. 아래 절의 "완료" 절에 요약을 남긴다.

## 프로젝트 todo 파일 (`docs/<name>-todo.md`)

프로젝트마다 루트 `docs/<프로젝트 디렉터리명>-todo.md` 파일 하나를 둔다.
프로젝트 저장소가 아니라 메타 저장소에 두는 이유는, 모든 프로젝트의 진행
상황과 이력을 루트 세션 한곳에서 파악하고 여러 기기에 동기화하기 위해서다.
결정 근거는 `docs/ssot/decisions/0004-todo-two-scopes-in-one-file.md` 참고.

한 파일이 **두 스코프**를 담는다.
- **프로젝트 스코프**: 프로젝트 전체 결정 사항, 다음 버전 계획, 완료된 버전의
  요약(이력). 프로젝트가 살아 있는 동안 계속 누적된다.
- **버전 스코프**: 지금 만들고 있는 버전 하나의 핵심 기능(요구사항)과 세부
  step. 릴리스되면 "완료" 절로 이동하면서 압축된다.

- 생성: `new-project` 스킬 1단계에서 생성하고, 부트스트랩 동안 결정 사항을 누적한다.
- 갱신: 프로젝트 세션이 작업 중 실시간으로 갱신한다. 프로젝트
  `.claude/settings.json`의 `additionalDirectories`로 `../../docs` 접근을 열어
  둔다(`docs/ssot/repo-architecture.md` "프로젝트 격리" 참고).
- 시행착오 제거: 탐색했다가 버린 대안과 중간 질문은 기록하지 않는다.
  A→B→C를 검토해 B로 결정했다면 B만 남긴다. 완료된 항목은 삭제하지 않고
  "완료" 절에 요약으로 남긴다.

### 파일 구조

```markdown
# <name> todo
저장소: <url> · 로컬: `projects/<name>/`
목적: <한 줄>

## 결정 사항
- 프로젝트 전체에 걸친 최종 결정 (스택, 구조, 정책)

## 진행 중: vX.Y <feature 이름>
- 컨텍스트: 왜 이 버전인가
- 핵심 기능 (모두 완료되면 릴리스):
  - [ ] 기능 A
  - [ ] 기능 B
- 세부 step:
  - [x] A-1 ...
  - [ ] A-2 ...
- 다음 행동: ...

## 다음 버전 (계획)
- vX.Z: 핵심 기능 후보를 한 줄씩

## 완료
- vX.Y (YYYY-MM-DD) <feature 이름>: 핵심 기능 요약
- (최신 버전이 위, 역순)

## 미확정 사항
```

### 절별 규칙
- **결정 사항**: 버전 작업 중 내린 결정이 프로젝트 전체에 영향을 주면 이 절로
  올린다. 그 버전에만 유효한 결정은 완료 절 항목에 함께 적는다.
- **진행 중**: 원칙적으로 버전 하나만 둔다. 핫픽스(patch)는 별도 절 없이
  완료 절에 한 줄만 남긴다. 핵심 기능이 모두 체크되면 릴리스한다.
- **완료**: 릴리스 시 "진행 중" 절에서 세부 step과 다음 행동을 제거하고,
  핵심 기능 목록을 1~3줄로 압축해 옮긴다. 개발 중 핵심 기능이 바뀌었다면
  최종 목록만 남긴다. 커밋 수준의 상세는 프로젝트 저장소 `CHANGELOG.md`가
  담당하므로 중복 서술하지 않는다. 최신 버전이 위에 오도록 역순으로 쌓는다.
- **다음 버전 (계획)**: 핵심 기능 후보만 적는다. 착수하면 "진행 중"으로
  올리고 세부 step을 채운다.

### 릴리스 시 처리 순서 (프로젝트 세션)
1. "진행 중" 절의 핵심 기능이 모두 체크되었는지 확인한다.
2. 프로젝트 저장소에서 `CHANGELOG.md`를 생성하고 태그를 만든다
   (`docs/ssot/repo-architecture.md` "버전·변경 이력" 참고).
3. 이 파일의 "진행 중" 절을 "완료" 절 맨 위로 옮기며 압축한다.
4. 메타 저장소를 commit·push한다.

## 갱신 규칙

이 문서는 사용자가 직접 갱신하거나, 루트 세션에서 사용자 승인 후에만
갱신한다(`CLAUDE.md`의 "가이드 우선" 원칙 참고).
